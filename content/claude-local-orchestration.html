Claude Hub와 로컬 LLM 보안 분석 구성

Claude 기반 관리자와 로컬 Ollama 모델, Hooks, MCP 및 실행 환경을 연결한 구성 문서다. 요청을 역할별 작업으로 나누고, 원본 도구 결과가 감사 로그와 보고서 입력으로 이어지는 흐름을 정리했다. 2026년 8월 문서의 구성·검증 기록을 설명한다.

1. 구성 요소와 역할

계층 역할
관리자·copilot 요청 해석, 스킬 선택, 다음 작업 연결
정찰·웹 분석·보고서 역할 각 단계의 입력과 결과 구분
로컬 모델 브릿지 로그 파싱, 생성 보조, 보고서 렌더 관련 처리
Hooks 범위 확인, 이벤트 기록, 큰 파일 처리 경로
MCP·실행기 보안 도구와 Kali·Windows 실행 환경 연결
산출물 JSONL 이벤트, 보고서, 재사용 가능한 스킬 기록 
자연어 요청 → 관리자와 스킬 선택
  → 역할별 작업
  → Hooks와 범위·기록 확인
  → MCP·실행기
  → 원본 결과와 로그
  → 보고서·재사용 스킬 정리

2. 로컬 모델과 외부 모델의 분담

판단과 작업 조정, 대량 로그 파싱·렌더 보조를 별도 역할로 나눴다. 문서에는 라우팅·파싱과 코드·보고서 생성 역할의 모델을 분리한 기록이 있다. 모델 이름이나 GPU 설정만으로 비용 절감과 처리 성능이 입증되는 것은 아니므로 비교 성과 수치는 기재하지 않는다.

3. 문서에 남은 개선 사례

문제 구성 기록
주소 형식 불일치 Ollama 주소의 스킴 정규화
import 시 종료 브릿지의 main 가드 처리
한국어 파일 읽기 UTF-8 인코딩을 명시한 읽기 경로
이벤트 스키마 충돌 확장 이벤트와 기존 훅 로그 분리
큰 로그 입력 관련 라인을 선택하는 Token Router 경로

이 기록은 도구를 설치한 사실뿐 아니라 연결 지점의 실패 원인과 수정 방향을 설명하는 자료다. 직접 개발 기여 범위와 현재 실행 상태는 별도로 확인해야 한다.

4. 결과물과 기록 기준

이벤트 로그를 보고서 입력으로 연결하고, 성공 흐름을 재사용 스킬로 정리하는 구조를 문서화했다. 원문에는 smoke 테스트 6단계 통과와 HTML 보고서 2건 생성이 기록돼 있다. 이는 당시 문서의 과거 결과이며 현재 랩에서 동일하게 재측정한 결과는 아니다.

5. 분석 결과를 다루는 기준

도구 호출 결과가 실패했거나 근거가 충분하지 않으면 보고서에서 성공한 작업으로 합치지 않는다. 대상 범위, 사람이 판단하는 지점, 로그의 원본과 공개용 마스킹을 연결하는 것이 이 구성에서 설명할 수 있는 경험이다.

  • Multi LLM MCP 워크벤치
  • 실행 상태와 증거 관리
