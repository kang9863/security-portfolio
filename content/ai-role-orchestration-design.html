AI 역할 분담과 검토 흐름 설계

redtm 구조도에 정리한 관리자·전문 검토·로컬 모델의 역할 분리 경험이다. 도구 호출 이전의 승인과 실행 이후 증거 대조를 한 흐름으로 연결하는 설계 자료다. 구조도만으로 운영 완료나 모델 비용 절감이 입증되는 것은 아니다.

1. 나눈 역할

역할 설계에서 맡기는 작업
관리자 요청과 작업 순서, 역할별 입력·출력 연결
전문 검토 보안·코드 분석의 결론과 근거 검토
로컬 모델 로그 정리와 반복적인 처리 보조
Token Router 긴 입력에서 관련 정보 선택
실행 게이트 범위와 승인 조건 확인
증거 기록 실행 결과와 최종 판단의 자료 연결

2. 역할을 나눠도 남는 문제

여러 모델이 같은 결론을 말하더라도 원본 자료가 같으면 독립적인 증거가 늘어난 것은 아니다. 각 역할의 입력이 무엇인지, 어떤 도구 결과를 근거로 결론을 냈는지 확인하는 흐름을 설계했다. 판단할 자료가 부족하면 추가 확인 항목으로 남겨야 한다.

3. Token Router와 증거 원본

긴 로그를 줄이는 처리와 원본을 보관하는 처리는 분리했다. 요약된 입력에는 빠진 조건이나 오류 메시지가 있을 수 있다. 구조도는 관련 정보 선택 후 전문 검토를 연결하지만, 실제 압축률·토큰 비용·분석 정확도 개선 수치는 확인되지 않아 기재하지 않는다.

4. 실행 전과 실행 후의 검토

요청과 계획 → 역할별 분석
  → 대상·도구·승인 확인
  → 실행 결과 수집
  → 원본 증거 대조
  → 결론 또는 추가 확인 항목

실행 전 승인만으로 실행 후 결과가 정확해지는 것은 아니다. 역할의 분업과 함께 결과 상태, 로그, 입력 조건을 확인해야 하는 점을 설계에 반영했다.

5. 자료의 범위

이 문서는 구조도에서 설명할 수 있는 설계 경험이다. 모든 역할·서버의 현재 연결 성공, 자동 검토 완성, 비용 절감 성과를 주장하지 않는다. 같은 워크벤치의 다른 구성도와 별개의 완성 제품 실적으로 중복 집계하지 않는다.
